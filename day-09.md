## Review

**Explain what a request is and what Burp’s Repeater does.**

A request is a message sent to the server asking for a response or information, and Burp's Repeater is a tool that lets us modify and resend the web request to see what the server would respond with and how

## 1. What is SQL injection?

SQL injection is a web security vulnerability that occurs when an application handles user input unsafely and allows that input to change the meaning of a database query.

## 2. Basic SQL

Example:

```sql
SELECT * FROM users
WHERE username = 'aylia';
```

- SELECT retrieves data.
- FROM identifies the table.
- WHERE filters the results.
- AND requires both conditions to be true.
- OR allows either condition to be true.
- -- begins a single-line SQL comment in supported dialects.

## 3. Why SQL injection happens

The application may combine user input directly with SQL code. An attacker may then manipulate the query's structure, potentially exposing data or bypassing authentication.

## 4. How to prevent it

Use parameterized queries (prepared statements) so user input is treated as data rather than executable SQL instructions. Handle passwords securely and apply appropriate access controls.

_**One more security detail:** applications should also store passwords using an appropriate password-hashing algorithm and verify them securely, rather than comparing plaintext passwords in a database. Parameterized queries remain essential even when password handling is done correctly._

# Lab Environment 

**Lab 1: SQL Injection in WHERE Clause Allowing Retrieval of Hidden Data**

_Objective:_ Retrieve products that were hidden by the website's normal product category filter.

_What I did:_

Opened the PortSwigger SQL injection lab.

Used Burp Suite to inspect the HTTP request generated when selecting a product category.

Found the category parameter in the request.

Sent the request to Burp Repeater so I could modify and resend it.

Modified the category parameter using the SQL injection test input provided by the lab.

Sent the modified request and inspected the response.

_What I learned:_

The website used a database query to filter products by category. Because the category input was handled unsafely, SQL injection could change the query's filtering logic.

The modified query could return products outside the selected category, including unreleased products that were supposed to remain hidden.

_Security impact:_ Sensitive or unreleased information could be exposed to users who should not be able to access it.

**Lab 2: SQL Injection Allowing Login Bypass**

_Objective:_ Understand how SQL injection can allow authentication to be bypassed.

_What I did:_

Opened the login-bypass lab.

Examined the login request and identified the relevant username and password parameters.

Used Burp Suite to inspect and test the request in the lab environment.

Applied the lab's SQL injection technique and submitted the modified request.

Observed the authentication result.

_What I learned:_

A vulnerable login query may check the supplied username and password using SQL conditions. If user input changes the query's logic, the application may authenticate a user without correctly validating the password.

_Security impact:_ An attacker could potentially gain unauthorised access to another user's account.
